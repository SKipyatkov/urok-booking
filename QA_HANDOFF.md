# QA Handoff — Urok Booking MVP

## 1. Что сделано

- [x] Регистрация преподавателя → создаётся `Organization` + `Teacher` + `User` (email как логин)
- [x] Вход / выход (Django auth)
- [x] Личный кабинет: календарь на неделю, расписание, ученики, бронирования, настройки
- [x] Настройка расписания: правила доступности по дням недели и часам (`AvailabilityRule`)
- [x] Настройки организации: название, описание, timezone, длительность слота (30/60 мин)
- [x] Публичная страница `/s/{slug}/book/` — выбор даты (HTMX), слоты, форма заявки
- [x] Генерация слотов из `AvailabilityRule` минус `Booking` и `BlockedSlot`
- [x] Публичная запись: `Student.status=new`, `Booking.status=pending`, `Booking.type=trial`
- [x] Защита от двойного бронирования: проверка в сервисе + `UniqueConstraint(teacher, starts_at)`
- [x] Rate limit на публичную форму (10 запросов/час с IP)
- [x] Email родителю и преподавателю при новой записи (console backend в dev)
- [x] Поле `meeting_url` на бронировании + кнопка «Открыть Телемост»
- [x] Смена статусов ученика и бронирования в кабинете
- [x] Django admin для всех моделей
- [x] Docker Compose (web + PostgreSQL)
- [x] Команда `seed_demo` для тестовых данных
- [x] Автотесты: слоты, бронирование, коллизия, публичная форма, регистрация, rate limit

## 2. Что не сделано / известные ограничения

- Один активный преподаватель на организацию (v1 — соло-репетитор)
- Нет UI для `BlockedSlot` (только Django admin)
- Нет напоминаний за 24ч/1ч
- Нет онлайн-оплаты, Jitsi, Telegram
- Slug организации не редактируется после регистрации
- Rate limit in-memory (сбрасывается при перезапуске; для прода нужен Redis)
- Страницы 404/500 не кастомизированы
- Пагинация учеников/бронирований — базовая Django

## 3. Как запустить

### Docker (рекомендуется)

```bash
cd urok-booking
cp .env.example .env
docker compose up --build
```

В другом терминале:

```bash
docker compose exec web python manage.py seed_demo
```

Открыть: http://localhost:8000

### Без Docker

```bash
cd urok-booking
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# В .env: DATABASE_URL=sqlite:///db.sqlite3
cd backend
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

## 5. Сценарии для ручного QA

1. **Регистрация** — открыть `/register/`, заполнить форму → редирект в `/cabinet/`, на дашборде видна публичная ссылка.
2. **Расписание** — `/cabinet/schedule/` → добавить правило (например, Пн 10:00–14:00) → правило в списке.
3. **Публичная страница** — открыть `/s/{slug}/book/` в инкогнито → видно название школы, выбор даты и слотов.
4. **Выбор слота** — выбрать дату с доступными слотами → кликнуть время → кнопка «Записаться» активна.
5. **Запись родителя** — заполнить форму, отправить → страница «Спасибо», в консоли web-контейнера 2 email.
6. **Кабинет: заявка** — войти как преподаватель → `/cabinet/bookings/` → новая заявка со статусом «Ожидает».
7. **Подтверждение** — открыть бронирование → статус «Подтверждён», вставить `meeting_url` → сохранить → кнопка «Открыть Телемост».
8. **Статус ученика** — `/cabinet/students/` → открыть ученика → сменить на «Пробный» → сохранить.
9. **Коллизия слотов** — две вкладки, один слот, две отправки → вторая получает ошибку «слот занят».
10. **Rate limit** — отправить >10 форм с одного IP за час → страница «Подождите» (429).

## 7. Риски и технический долг

| Риск | Что проверить |
|------|---------------|
| Timezone | Слоты и отображение времени при timezone ≠ Europe/Moscow |
| Граница дня | Запись около полуночи по местному времени |
| HTMX | Смена даты на мобильном, обновление слотов без перезагрузки |
| Race condition | Два одновременных POST на один слот (constraint должен сработать) |
| Rate limit | In-memory cache не работает между несколькими gunicorn workers |
| WhiteNoise | `collectstatic` при первом docker build |
| Slug collision | Регистрация с одинаковым названием → суффикс `-1`, `-2` |

**Приоритет для QA:** публичный поток записи, email в консоли, смена статусов, meeting_url.
